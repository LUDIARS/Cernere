# GLab 在校生・OB登録

登録画面は Cernere の `glab.signup_fields` version 3 が所有する。
「在校生」「OB」のタブで `member_type` (`student` / `alumni`) を選択する。

| 項目 | 在校生 | OB |
|---|---|---|
| 名前 | 必須 | 必須 |
| ニックネーム | 任意 | 任意 |
| 役職 | 必須 | 必須 |
| 学科 | 必須 | 非表示 |
| 学年 | 必須（1以上の整数） | 非表示 |
| 会社 | 非表示 | 任意 |

プロフィールの正本は Cernere `project_data_glab`。GLab SQLite に複製しない。
既存の氏名・役職・学科・学年は保持する。未選択の既存ユーザーにも所属区分を確認し、
在校生には不足した学年を求める。OBの学科・学年は登録完了条件にしない。
非表示項目の送信値は Cernere で無視し、以前の値は保持する。
タブ間の切替中は入力値を保持する。ニックネームは登録情報であり公開表示名の設定を変更しない。

反映順: Cernereの条件付き項目対応 → migration 079 とサービス宣言 → GLabの完了判定。
本番データ変更・再起動はこの実装作業では実行していない。
新規依存・外部送信先は追加せず、既存の認証済みプロフィール保存経路のみを使用する。
検証用ケースは追加するが、実行は Revisor の審査に委ねる。

## 共通入力宣言

`input: tabs` は text 列の選択肢をタブ表示する。
`visible_when: { column, value }` は同一source・moduleの無条件な必須selectorだけを参照可能。
`minimum` は number 入力だけに宣言できる。全経路の保存時に検証する。
条件付き宣言は切替先の必須値を同一リクエストで検証できるよう全許可列を返す。
拒否module・共有grantの既存境界を維持する。隠れた列は必須判定・書込み対象外。
